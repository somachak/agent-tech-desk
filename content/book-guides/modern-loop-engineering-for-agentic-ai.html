01 · Where this is going

Reliable intelligence comes from the loop around the model, not from the model: observe, reason, act, evaluate, improve, with control at every step.

Read this book when: Open it when your agent works in a demo but you cannot say why it stopped, what it may touch, or how it gets better.

The one picture that holds the whole book. Every chapter adds a box or an arrow to it; nothing later replaces it.

flowchart LR
  A[Objective] --> B[Observe]
  B --> C[Reason - model proposes]
  C -->|proposed action| D[Control layer]
  D -->|allowed| E[Act - run tool]
  D -->|needs approval| H[Human]
  H --> E
  E --> F[Evaluate - gate]
  F -->|pass| G[Done]
  F -->|fail and budget left| B
  F -->|budget spent| S[Stop]
  F -->|many runs| I[Improve rules]
  I --> C

  2. Mark each event as observe, reason, act, evaluate or improve.
  3. Set max_steps to 2 and watch the budget_exhausted event appear.
  4. Write one sentence: did the model stop the run, or did the loop?

Steps for rung 2: Recovery ladder, checkpoints and provisional memory

  1. Add a retry counter to the gate feedback in agent.py; after two fails, stop and ask.
  2. Log an evaluation event for every gate verdict, with the reasons list.
  3. Add a `provisional` list to memory.py that holds new claims with source and date.
  4. Promote a claim into the drawer only after catalogue_lookup confirms it.
  5. Put a timeout around read_supplier_page and record it in the Glass Box.
Chapters 4, 6, 7, 10 · Agent Lab files: agent.py · memory.py · glassbox.py · formulaite_tools.py · ~half a day

Steps for rung 3: Governed tools, injection defence and a cost-aware eval

  1. Tag every tool in tools.py as read or write; block write tools without approval.
  2. Wrap supplier page text as data in formulaite_tools.py and strip imperative lines.
  3. Validate tool outputs against the catalogue range before they touch the drawer.
  4. Run all five catalogue ingredients through the loop; record steps, gate fails and token estimate.
  5. Add a red-team supplier page with a hidden instruction and check the gate still holds.
Chapters 8, 9, 10, 13 · Agent Lab files: tools.py · formulaite_tools.py · gates.py · memory.py · ~2 days

01A model is not an agent ch 1

A language model only produces text from learned patterns. An agent wraps that model with memory, planning, tools and evaluation. The loop around the model is what acts. Build the loop, not just the prompt.

Picture it: A recipe book is the model. The formulator with a bench, a scale and a tasting habit is the agent.
from agent_lab import Agent, GlassBox, ScriptedModel, build_registry

model = ScriptedModel()                     # the brain, swappable
tools = build_registry()                    # the hands
box = GlassBox(run_id="glycerin-001")       # the flight recorder
agent = Agent(model, tools, glassbox=box)   # model + loop = agent
result = agent.run("Glycerin")
print(result.ok, result.steps)
Agent is built from four swappable parts; the model is only one of them.
The trap: Treating a better prompt as the fix when the missing piece is a loop stage.
In Formulaite: agent.py composes the model, the tool registry, the Glass Box and the gate into one loop.
02The five-stage loop ch 1

Every turn moves through five stages: observe, reason, act, evaluate, improve. Observe gathers facts, reason picks an action, act runs it. Evaluate checks the result and improve changes the next turn. Name the stage and you can debug the turn.

Picture it: Making an emulsion: look at the beaker, decide to add oil, pour, check for splitting, adjust the next batch.
for step in range(1, max_steps + 1):
    facts = convo.as_api()                                # observe
    reply = model.complete(system, facts, tools)          # reason
    drawer = run_tools(reply.tool_uses)                   # act
    verdict = run_gates(drawer, catalogue_entry=entry)    # evaluate
    if verdict.passed:
        break
    convo.add_tool_results(feedback(verdict.reasons))     # improve next turn
One loop body, five labelled lines; the labels are the stages.
The trap: Skipping evaluate and going straight from act to the next reason step.
In Formulaite: agent.py's for-loop is the five stages; the gate verdict is the evaluate stage.
03Loop control ch 1

An agent must never keep acting without checking progress. Loop control adds step limits, checkpoints, approval points and failure rules. The limit is a budget the model cannot argue with. It turns a runaway into a clean stop.

Picture it: A kitchen timer. However good the cook, the oven turns off at the set time.
agent = Agent(model, tools, max_steps=8)
result = agent.run("Glycerin")
if not result.ok:
    print(result.final_text)     # "Stopped after 8 steps without an accepted drawer."
    for e in result.glassbox.replay():
        if e.kind == "budget_exhausted":
            print("stopped by the loop, not by the model")
max_steps is set outside the model; the for/else in agent.py logs the stop.
The trap: Setting the limit so high that a stuck loop burns a whole budget before anyone notices.
In Formulaite: agent.py's max_steps and the budget_exhausted Glass Box event.
04Separate intelligence from control ch 1

The model proposes. Engineered layers decide what is allowed, verify results and call a human. Keep these two jobs in different code. Then a confident wrong answer cannot become a wrong action.

Picture it: A junior formulator suggests a recipe; the lab manager signs off before anything is mixed.
drawer = IngredientDrawer.from_model_input(**call.input)   # intelligence
verdict = run_gates(drawer, catalogue_entry=entry)          # control
if verdict.passed:
    accept(drawer)
else:
    send_back("REJECTED by gate:\n- " + "\n- ".join(verdict.reasons))
The gate has no model inside it; it only compares against the catalogue and fixed rules.
The trap: Asking the model to grade its own answer and calling that a gate.
In Formulaite: gates.py is the control layer, models.py is the intelligence layer, agent.py keeps them apart.
05Two loops, two speeds ch 1

One fast loop finishes the task in front of you. One slow loop looks at many runs and improves the rules. Keep them apart. The fast loop must not rewrite itself mid-task.

Picture it: Cooking tonight's dinner is the fast loop. Rewriting the recipe card after ten dinners is the slow loop.
The trap: Letting one bad run change the system prompt on the spot.
In Formulaite: The fast loop is Agent.run() in agent.py; the slow loop is you reading Glass Box traces and editing gates.py.
06The seven layers ch 2

A full agent has seven layers: perception, reasoning, planning, memory, execution, evaluation, governance. Each does one job. Strength comes from how well they hand work to each other, not from any single layer.

Picture it: A formulation lab: goods-in, the chemist, the batch plan, the notebook, the mixing bench, QC, and the safety officer.
The trap: Building a huge reasoning layer and leaving evaluation and governance as afterthoughts.
In Formulaite: Map: tools.py is perception and execution, models.py reasoning, memory.py memory, gates.py evaluation, glassbox.py the governance record.
07The execution layer ch 2

Execution is where decisions touch the world. It needs a permission check before, validation after, and a recovery path when things fail. A tool call is never just a function call.

Picture it: Dispensing a raw material: check the label, weigh it, log it, and have a plan if the drum is empty.
def _handle_tool(self, call, inci):
    try:
        output = self.tools.call(call.name, **call.input)
        text, is_error = as_text(output), False
    except ToolError as exc:
        text, is_error = f"ERROR: {exc}", True     # never crash the loop
    self.glassbox.log("tool_call", inci, tool=call.name, ok=not is_error)
    return _tool_result(call.id, text, is_error)
Errors become a tool_result the model can read; the loop keeps control.
The trap: Letting a tool exception crash the whole run instead of feeding it back.
In Formulaite: agent.py's _handle_tool wraps every call from tools.py in try/except and logs it.
08Closed loop versus open loop ch 3

An open loop acts and never looks back. A closed loop measures the result and adjusts. Use open loops for stable, low-stakes tasks. Use closed loops wherever mistakes must be caught automatically.

Picture it: A kettle that boils for three minutes is open loop. A thermostat that checks and adjusts is closed loop.
# open loop: one shot, no check
drawer = model_fill_drawer("Glycerin")

# closed loop: check, feed back, repeat
feedback = ()
for _ in range(max_steps):
    drawer = model_fill_drawer("Glycerin", feedback)
    verdict = run_gates(drawer, catalogue_entry=entry)
    if verdict.passed:
        break
    feedback = verdict.reasons
The only difference is the verdict feeding the next attempt.
The trap: Adding a loop but never sending the failure reasons back, so every retry is identical.
In Formulaite: agent.py closes the loop by returning gate reasons as an error tool_result.
09Feedback needs a target ch 3

Feedback only means something against a clear objective. If success is vague, the agent cannot tell a good result from a bad one. Write the target down first. Then every check compares against it.

Picture it: You cannot say a cream is too thick without knowing the viscosity you wanted.
class IngredientDrawer:
    REQUIRED_SECTIONS = (
        "inci_name", "function", "typical_use_level", "use_level_pct",
        "phase_and_solubility", "ph_range", "compatibility",
        "safety_notes", "sources",
    )

    def missing(self) -> list[str]:
        return [n for n in self.REQUIRED_SECTIONS if _is_empty(getattr(self, n))]
The target is a fixed list of sections; missing() is the first check.
The trap: Telling the agent to research glycerin with no definition of done.
In Formulaite: drawer.py's REQUIRED_SECTIONS is the objective the whole loop aims at.
10Four ways to evaluate ch 3

Evaluation can come from automated tests, an outside source, a human, or a fixed standard. Pick one per step. Cheap checks run every turn. Expensive ones run at milestones.

Picture it: QC on a batch: the pH meter, a reference sample, a colleague's nose, and the spec sheet.
The trap: Using the model's own confidence as the only evaluator.
In Formulaite: gates.py holds fixed-standard checks; catalogue_lookup is the outside source; the human is you reading the Glass Box.

01Recognise uncertainty, then ask ch 4

A reliable agent knows when it lacks information. It estimates confidence before acting. If confidence is low it gathers more, compares sources, or asks a human. A confident guess is worse than a question.

Picture it: A formulator unsure of a preservative's maximum level checks the datasheet before weighing.
entry = catalogue_lookup(inci)
if entry is None:
    return "Unknown ingredient - ask the user before filling the drawer"
if entry.get("banned"):
    return f"{inci} is banned - stop here"
page = read_supplier_page(entry["supplier_url"])
The first two branches are the agent choosing not to act.
The trap: Filling every drawer section anyway and hoping the gate catches the invented parts.
In Formulaite: SYSTEM_PROMPT rule 1 in agent.py: if the ingredient is unknown or banned, say so and stop.
02Verify before important actions ch 4

Before a step that matters, add a check. Options: self-review, a rule check, a second system, or a human. Compare two independent paths when the stakes are high. Knowing when not to act is part of intelligence.

Picture it: Two people count the raw material weights on a batch sheet before mixing.
The trap: Verifying only at the very end, after cheap early errors have compounded.
In Formulaite: run_gates in gates.py is the rule check before a drawer is accepted.
03The recovery ladder ch 4

Errors are normal. Detect them fast, then climb a ladder: retry, try another approach, ask for information, hand to a human. Each rung costs more. Never skip to the top, never loop forever on the bottom.

Picture it: A stuck emulsion: stir again, change the mixing speed, check the recipe, call the senior chemist.
for attempt in range(3):
    verdict = run_gates(drawer, catalogue_entry=entry)
    if verdict.passed:
        break
    if attempt == 0:
        drawer = retry_with(verdict.reasons)        # rung 1: retry
    else:
        drawer = try_other_source(entry)            # rung 2: alternative
else:
    hand_to_human(verdict.reasons)                  # top rung
The attempt number picks the rung; the for/else is the hand-over.
The trap: Retrying the same call with the same input and expecting a different answer.
In Formulaite: agent.py sends gate reasons back for the retry rung; the hand-over rung is the budget_exhausted stop.
04Staged workflows ch 6

Split a big job into stages. Each stage's output is the next stage's input. Every hand-off is a place to check and to log. A failure in one stage does not restart the whole job.

Picture it: Weigh, heat, mix, cool, test. You do not re-weigh because the cooling step failed.
The trap: One giant prompt that asks for the whole report in a single shot.
In Formulaite: The Formulaite loop has three stages, catalogue_lookup, read_supplier_page, fill_drawer, each logged by glassbox.py.
05Adaptive planning ch 6

Plans are guesses. Split the goal into subtasks, tag each with risk and priority, then reassess as facts arrive. Sequential steps need order, parallel steps can run together. High-risk steps get extra checks.

Picture it: A stability study plan changes when week two shows separation.
The trap: Treating the first plan as fixed and pushing through when the facts have changed.
In Formulaite: Would live in agent.py as a plan list the model updates after each tool result.
06Timeouts and checkpoints ch 6

Every operation gets a time limit. Every stage saves its state. A crash or an approval wait then resumes instead of restarting. Give the operator pause, resume and stop controls.

Picture it: Writing the batch record as you go, so a power cut does not mean starting from raw materials.
import json, signal

def checkpoint(box: GlassBox, path: str) -> None:
    with open(path, "w") as f:
        json.dump([e.__dict__ for e in box.replay()], f)

signal.alarm(30)                     # timeout for the next stage
page = read_supplier_page(url)
signal.alarm(0)
checkpoint(box, "run.json")
The alarm bounds one stage; the checkpoint writes the trace so far.
The trap: A supplier page that never loads, and a run that waits on it forever.
In Formulaite: Would wrap read_supplier_page in formulaite_tools.py and dump the GlassBox after each stage.
07Short-term and long-term memory ch 7

Short-term memory is the current task: instructions, tool results, unfinished state. It is thrown away at the end. Long-term memory keeps facts, past episodes and workflow templates. Load only what the task needs.

Picture it: The scrap paper on the bench versus the lab's bound notebook.
convo = Conversation()          # short-term: lives for one run
convo.add_user("Research the ingredient: Glycerin")
convo.add_assistant(blocks)
convo.add_tool_results(results)
print(convo.token_estimate())   # how big is short-term memory now?

catalogue = load_catalogue()    # long-term: facts that outlive the run
Conversation lives for one run; the catalogue lives across runs.
The trap: Putting everything the agent ever saw into every call.
In Formulaite: memory.py is short-term memory; data/catalogue.json read by formulaite_tools.py is long-term semantic memory.
08Context compression and freshness ch 7

Long runs collect more text than the model can use. Summarise the old parts and keep the essentials. Mark when each fact was retrieved. Old facts need re-checking before they drive a decision.

Picture it: A one-page batch summary replaces forty pages of notes, with the date on top.
The trap: Compressing away the exact numbers the gate later needs.
In Formulaite: Would live in memory.py as a summarise() step when token_estimate() crosses a budget.
09Provisional storage ch 7

New claims do not go straight into long-term memory. They wait in a staging area until validated. Rank sources by trust and prune what stops being useful. This stops one bad page from poisoning every future run.

Picture it: A quarantine shelf for incoming raw materials until the certificate of analysis checks out.
provisional: list[dict] = []
long_term: list[dict] = []

def stage(claim: str, source: str) -> None:
    provisional.append({"claim": claim, "source": source, "validated": False})

def promote(entry: dict) -> None:
    for item in provisional:
        if item["claim"] in entry.get("facts", []):
            item["validated"] = True
            long_term.append(item)
Nothing reaches long_term without passing through validated=True.
The trap: Writing supplier marketing claims into the catalogue as facts.
In Formulaite: Would live in memory.py as a staging list; catalogue_lookup in formulaite_tools.py is the validator.
10Provenance on every fact ch 7

Each stored fact carries its origin, date, revision and validation status. Then anyone can judge how much to trust it. Provenance is what turns a claim into evidence.

Picture it: A certificate of analysis: supplier, batch, date, and who tested it.
from dataclasses import dataclass

@dataclass(frozen=True)
class Fact:
    text: str
    source: str         # tool name or page URL
    retrieved_at: str   # ISO date
    validated: bool = False
Frozen, so a fact's history cannot be quietly edited later.
The trap: A drawer with numbers but no sources list.
In Formulaite: drawer.py's sources field and check_has_sources in gates.py enforce the minimum provenance.
11Logging, tracing, auditing ch 10

Logs are single events with a timestamp and ids. Tracing links events into one run's path. Auditing keeps tamper-resistant records for accountability. Same data, three purposes.

Picture it: Bench notes, the batch record that strings them together, and the signed QC file.
box = GlassBox(run_id="glycerin-001")
box.log("tool_call", "glycerin", tool="catalogue_lookup", ok=True)   # log
box.log("gate", "glycerin", passed=False, reasons=["no sources"])

for event in box.replay():        # trace: the events in order
    print(event.as_line())
log() is logging; replay() in order is the trace; run_id is the audit key.
The trap: Free-text print statements that no tool can filter or link.
In Formulaite: glassbox.py: Event is the log entry, replay() is the trace, run_id ties the audit together.
12Observability explains why ch 10

Monitoring says whether the run succeeded. Observability says why. Record intermediate decisions, retrieved facts, options considered and retries. Choose the level of detail on purpose.

Picture it: A failed batch with only FAIL on the sheet teaches nothing. One with every reading teaches everything.
The trap: Logging every token and drowning the one gate reason that matters.
In Formulaite: glassbox.py records model_reply, tool_call and gate events so why-did-it-stop is answerable.

01Cost governance ch 5

Cost comes from repeated reasoning, duplicate retrieval and idle agents. Classify each task by urgency and importance. Cache frequent lookups and set quotas and budgets. Retire what is unused.

Picture it: Buying the same raw material three times because nobody checked the store cupboard.
from functools import lru_cache

@lru_cache(maxsize=1)
def load_catalogue() -> dict:
    return json.loads(CATALOGUE_PATH.read_text())   # read once, reuse

TOKEN_BUDGET = 20_000
if convo.token_estimate() > TOKEN_BUDGET:
    stop("token budget spent")
lru_cache stops duplicate retrieval; the token check is a quota.
The trap: Measuring cost only at the end of the month, not per run.
In Formulaite: formulaite_tools.py caches the catalogue; memory.py's token_estimate() is the per-run budget signal.
02Constraints that cannot be bypassed ch 8

Policies say what an agent may do. Technical controls enforce them in code. Some steps are mandatory: a review stage, an approval checkpoint. No amount of clever reasoning can skip them.

Picture it: The safety data sheet check happens before any new material enters the lab, whoever asks.
def run_gates(drawer, *, catalogue_entry=None, checks=DEFAULT_CHECKS):
    entry = catalogue_entry or {}
    reasons = [r for check in checks if (r := check(drawer, entry)) is not None]
    return GateVerdict(passed=not reasons, reasons=tuple(reasons))
The checks tuple is fixed in code; the model cannot remove a check.
The trap: Putting the rule in the system prompt and trusting the model to follow it.
In Formulaite: gates.py DEFAULT_CHECKS, including check_not_banned, run whether the model likes it or not.
03Minimum necessary access ch 8

Each agent gets only the permissions its job needs. Group permissions by role and split sensitive workflows across agents. Temporary permissions expire. Every access is logged with the agent's identity.

Picture it: The intern can read the formulation database but cannot approve a supplier.
class Tool:
    def __init__(self, fn, *, name, description, writes: bool = False):
        self.fn, self.name, self.writes = fn, name, writes

class ToolRegistry:
    def call(self, name, *args, approved: bool = False, **kwargs):
        tool = self[name]
        if tool.writes and not approved:
            raise ToolError(f"{name} writes state - needs approval")
        return tool(*args, **kwargs)
A writes flag on the tool, and the registry refuses without approval.
The trap: Giving every tool to every agent because it might be useful later.
In Formulaite: Would live in tools.py as a read/write flag on Tool and a check in ToolRegistry.call.
04Oversight models ch 8

Three levels: approve every action, supervised autonomy with escalation rules, progressive autonomy earned over time. Pick by risk. Low-risk reads run alone. Writes and money wait for a human.

Picture it: A new formulator has every batch signed off. After a year, only the new actives are.
The trap: Too much oversight kills efficiency; too little kills reliability.
In Formulaite: Would live in agent.py as an approval hook on fill_drawer, relaxed as gate pass rates improve.
05Instructions are not data ch 9

Retrieved text can contain hidden instructions. Treat everything the agent reads as data with no authority. Keep it apart from the system prompt. Enforce policy in code, so even a fooled model cannot break a rule.

Picture it: A supplier brochure that says ignore your QC limits is still just a brochure.
def read_supplier_page(url: str) -> str:
    text = fetch(url)
    lines = [l for l in text.splitlines()
             if not l.strip().lower().startswith(("ignore", "you must", "system:"))]
    return "<supplier_page_data>\n" + "\n".join(lines) + "\n</supplier_page_data>"
Wrapped as data and stripped of imperative lines before the model sees it.
The trap: Pasting a web page straight into the prompt next to the rules.
In Formulaite: formulaite_tools.py read_supplier_page should wrap page text as data; gates.py enforces limits regardless.
06Validate tool outputs too ch 9

Inputs to tools get checked. Outputs from tools deserve the same. A service can return garbage, an error, or a planted instruction. Check schema and sanity ranges before results touch state.

Picture it: A pH reading of 14 for a face cream is wrong, whatever the display says.
def check_use_level_in_range(drawer, entry):
    if not entry or drawer.use_level_pct is None:
        return None
    lo, hi = entry["use_level_min"], entry["use_level_max"]
    if not (lo <= drawer.use_level_pct <= hi):
        return f"use_level_pct {drawer.use_level_pct}% is outside {lo}-{hi}%"
    return None
A sanity range on the model's output, taken from the catalogue not from the page.
The trap: Trusting a tool result because the tool is yours.
In Formulaite: gates.py check_use_level_in_range validates the model's output against the catalogue.
07Red-team evaluation ch 9

Normal tests check the happy path. A red team tries to break the agent: planted instructions, conflicting rules, boundary cases. Find the weakness before a real supplier page does. Keep testing after deploy.

Picture it: Deliberately contaminating a test batch to prove the preservative system works.
The trap: Testing only with the three clean ingredients that always pass.
In Formulaite: Would live as a data/pages file with a hidden instruction, run through agent.py to prove the gate holds.
08Specialised roles ch 12

Big jobs split across agents with clear roles: planner, retriever, executor, validator, monitor. Few agents can talk directly. Many agents need a coordinator. Messages carry task id, priority, status and validation result.

Picture it: A lab team: one plans the study, one sources materials, one mixes, one runs QC, one keeps the log.
The trap: Five agents with overlapping jobs, each redoing the other's work.
In Formulaite: Would split agent.py into a retriever agent and a validator agent, with GlassBox events as the shared record.
09Self-improvement under governance ch 12

A self-improving agent does not rewrite itself. It proposes a change from evidence. The change is tested, versioned and approved before it enters the loop. One odd run must never change the rules.

Picture it: A recipe tweak goes through a trial batch and a sign-off before the master formula changes.
The trap: Letting the model edit its own system prompt after a failure.
In Formulaite: The improve stage is you editing SYSTEM_PROMPT or gates.py after reading many Glass Box traces.
10Feedback drift ch 3

Drift is when the agent gets better at the rewarded signal and worse at the real goal. It comes from bad metrics or shifting data. Watch for it and keep boundaries fixed. Avoid metrics that reward bad behaviour.

Picture it: Rewarding speed alone and getting batches that pass fast and fail on the shelf.
The trap: Optimising gate pass rate until the gate is what the model games, not the truth.
In Formulaite: Track gate pass rate and reasons per run from glassbox.py; a sudden jump in passes is a drift flag.
11Repeatable benchmarks ch 13

A benchmark is a fixed set of tasks run the same way every time. Measure completion, accuracy, consistency, latency and cost. Include odd cases. Repeat after every change to catch regressions.

Picture it: The same five reference formulas tested on every new batch of raw material.
INCIS = ["Glycerin", "Coco-Glucoside", "Xanthan Gum",
         "Phenoxyethanol", "Methylisothiazolinone"]   # last one is banned
rows = []
for inci in INCIS:
    r = Agent(ScriptedModel(), build_registry()).run(inci)
    fails = sum(1 for e in r.glassbox.replay()
                if e.kind == "gate" and not e.meta["passed"])
    rows.append({"inci": inci, "ok": r.ok, "steps": r.steps, "gate_fails": fails})
Same list, same model, same registry; the rows are comparable across versions.
The trap: A benchmark with only tasks the agent already passes.
In Formulaite: An evals script over agent.py runs, reading steps, gate fails and token_estimate from each RunResult.
12Faithful explanations ch 14

An explanation must reflect what actually happened, not a plausible story. Link each decision to the evidence and policy behind it. Separate verified facts from guesses. Say how confident you are.

Picture it: A batch deviation report that names the real cause, not the convenient one.
The trap: Asking the model to explain its reasoning after the fact and calling that a trace.
In Formulaite: glassbox.py is the faithful record; the drawer's sources field in drawer.py is the evidence link.
05 · Cheat sheet

Modern Loop Engineering for Agentic AI — cheat sheet

Everything on one sheet.

Vocabulary

TermMeans
Loop engineeringDesigning an agent as repeated cycles of observe, reason, act, evaluate, improve.
AgentA model plus memory, planning, tools, evaluation and the power to act.
ObservationGathering the facts the next decision needs; its quality caps decision quality.
EvaluationChecking whether an action achieved the intended result.
Loop controlStep limits, checkpoints, approvals and failure rules that stop a runaway.
Closed loopA system that measures its own results and adjusts.
Open loopA system that acts once and never looks back.
Feedback driftGetting better at the rewarded signal and worse at the real goal.
Execution layerWhere decisions touch the world: permissions, validation, recovery, monitoring.
Short-term memoryTask-local context, discarded when the task ends.
Long-term memorySemantic facts, episodic history and procedural templates that outlive a task.
Provisional storageA staging area for unverified claims before they may enter long-term memory.
ProvenanceOrigin, date, revision and validation status attached to a fact.
Context isolationRetrieved text gets no authority over the agent's rules.
ObservabilityEnough recorded evidence to explain why an outcome happened.
TraceLog events linked into one run's execution path.
Audit trailTamper-resistant records that tie actions to an identity for accountability.
CheckpointSaved workflow state so a run resumes instead of restarting.
Red teamPeople who try to break the agent on purpose before an attacker does.
Oversight modelHow much autonomy an agent gets: approve-all, supervised, or progressive.

The pattern

  1. objective = what done looks like (the drawer sections)
  2. for step in range(max_steps):
  3. observe: gather facts from memory and tools
  4. reason: model proposes one action
  5. control: is it allowed? needs a human? then act
  6. evaluate: deterministic gate, log the verdict
  7. pass -> stop; fail -> feed reasons back
  8. after many runs: improve the rules, never mid-run

Decisions

WhenUseNot
The task is stable and a mistake is cheapan open loop, one shota full closed loop with gates
A mistake reaches the drawer or a customera closed loop with a deterministic gatethe model's own confidence
The gate fails for the first timeretry with the reasons as inputhand to a human straight away
The gate fails twice with the same reasonanother source or a humana third identical retry
A supplier page has a new claimprovisional storage with source and datethe catalogue
A tool writes state or spends moneyapproval before the callsupervised autonomy
You have two agentsdirect messagesa coordinator
You have many agentsa coordinator and standard messagesa web of direct links

Rules of thumb

DoDon't
Put the stop condition in code (max_steps, timeouts).Ask the model to decide when it has done enough.
Keep the gate free of any model call.Let the model grade its own drawer.
Send gate reasons back as the next input.Retry with identical input and hope.
Stage new claims with source and date, then validate.Write supplier claims straight into the catalogue.
Wrap retrieved text as data with no authority.Paste a web page next to the system rules.
Validate tool outputs against sanity ranges.Trust a result because the tool is yours.
Log one event per loop stage with ids and a timestamp.Print free text nobody can filter.
Give tools a read or write class; gate the writes.Hand every tool to every agent just in case.
Change rules in the slow loop after many traces.Rewrite the system prompt after one bad run.
Benchmark the same tasks after every change, with cost.Test only the ingredients that already pass.

Skeletons

Five-stage loop with budget

for step in range(1, max_steps + 1):
    reply = model.complete(system, convo.as_api(), tools.to_api())  # observe+reason
    if not reply.tool_uses:
        break                                                      # model answered
    results = [run_tool(c) for c in reply.tool_uses]               # act
    verdict = gate_if_answer(results)                              # evaluate
    box.log("gate", inci, passed=verdict.passed, reasons=verdict.reasons)
    if verdict.passed:
        break
    convo.add_tool_results(results)                                # improve next turn
else:
    box.log("budget_exhausted", inci, max_steps=max_steps)

Deterministic gate

def check_has_sources(drawer, entry):
    return None if drawer.sources else "no sources listed"

def run_gates(drawer, *, catalogue_entry=None, checks=DEFAULT_CHECKS):
    entry = catalogue_entry or {}
    reasons = [r for check in checks if (r := check(drawer, entry)) is not None]
    return GateVerdict(passed=not reasons, reasons=tuple(reasons))

Provisional memory with provenance

@dataclass(frozen=True)
class Fact:
    text: str
    source: str
    retrieved_at: str
    validated: bool = False

provisional: list[Fact] = []

def promote(fact: Fact, catalogue: dict) -> Fact | None:
    ok = fact.text in catalogue.get("facts", [])
    return Fact(fact.text, fact.source, fact.retrieved_at, True) if ok else None

Retrieved text as data

def as_data(text: str) -> str:
    keep = [l for l in text.splitlines()
            if not l.strip().lower().startswith(("ignore", "you must", "system:"))]
    return "<supplier_page_data>\n" + "\n".join(keep) + "\n</supplier_page_data>"

Before you ship

  • before you ship, check max_steps and a timeout exist on every run and every tool call
  • before you ship, check the gate has no model call inside it
  • before you ship, check every gate verdict is logged with its reasons
  • before you ship, check retrieved text is wrapped as data and never edits the rules
  • before you ship, check every drawer has at least one source
  • before you ship, check write tools need approval and read tools are logged
  • before you ship, check the benchmark includes a banned and an unknown ingredient
  • before you ship, check the trace can answer why the run stopped
06 · You're done when…
  1. You can point at a Glass Box trace and name the loop stage of every event, including the one that stopped the run.
  2. You can make the gate reject a drawer, watch the reasons go back, and see the next attempt fix exactly those.
  3. You can plant an instruction in a supplier page and show the gate still blocks the out-of-range use level.
