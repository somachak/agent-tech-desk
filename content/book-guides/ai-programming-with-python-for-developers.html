01One client layer for the model ch 1

Put every model call in one small function like generate_text(). The rest of the app sends a string and gets a string back. Timeouts, retries, logging and the model name then live in one place. Nothing else needs to know which provider you use.

Picture it: It is the single tap in a lab. Every bench draws water from it, so you change the filter once, not at every bench.
from openai import OpenAI
from .config import get_api_key, get_model

def create_client() -> OpenAI:
    return OpenAI(api_key=get_api_key(), timeout=30.0, max_retries=2)

def generate_text(prompt: str) -> str:
    client = create_client()
    response = client.responses.create(model=get_model(), input=prompt)
    return response.output_text
The model name comes from config; timeout and retries sit on the client, not in every caller.
The trap: Creating a client in five different files, so one timeout change means five edits.
In Formulaite: models.py: ClaudeModel.complete() is the single place the Agent Lab talks to Claude.
02Translate errors at the boundary ch 1

A model request is a network call and it can fail. Catch the provider's errors in the client layer and re-raise one app error with from exc. Never swallow an unexpected error and return an empty string. That hides the real problem.

Picture it: A receptionist turns 'ERR 503 upstream' into 'the lab is closed today' but keeps the original note on file.
from openai import APIError, APITimeoutError, RateLimitError
def generate_text(prompt: str) -> str:
    client = create_client()
    try:
        response = client.responses.create(model=get_model(), input=prompt)
        return response.output_text
    except APITimeoutError as exc:
        raise RuntimeError("The model request timed out.") from exc
    except RateLimitError as exc:
        raise RuntimeError("The model service rate limit was reached.") from exc
    except APIError as exc:
        raise RuntimeError(f"Model request failed: {exc}") from exc
from exc keeps the original cause attached for debugging.
The trap: except Exception: return "" makes an outage look like a model with nothing to say.
In Formulaite: tools.py: ToolError is the one error type tools raise; agent.py turns it into an error tool_result instead of crashing.
03Dependency injection by argument ch 1

Pass the thing a function needs as an argument instead of importing it. summarize_document(text, generator) does not care if generator is OpenAI, Ollama or a fake. No framework is needed. A plain Python parameter is enough.

Picture it: A recipe says 'add your emollient of choice' rather than naming one brand. You swap it without rewriting the recipe.
def summarize_document(text: str, generator) -> str:
    if not text.strip():
        raise ValueError("Document cannot be empty.")
    prompt = f"""
    Summarize the following document in five concise bullet points.
    Document: {text}
    """
    return generator(prompt)

summary = summarize_document(document, generate_text)
generator is just a callable; in tests you pass a fake function.
The trap: Importing generate_text directly inside the function, so every test must hit the real API.
In Formulaite: agent.py: Agent(model=..., tools=..., glassbox=...) receives its parts, so ScriptedModel swaps for ClaudeModel with one flag.
04Fake the model in tests ch 1

Most of your code is ordinary Python. Test it with a fake generator that returns a fixed string. Check that validation rejects bad input before the model is ever called. Save live calls for a few deliberate integration tests.

Picture it: You test the pump with water before you fill it with expensive serum.
import pytest

def test_summarize_document():
    def fake_generator(prompt: str) -> str:
        assert "Project update" in prompt
        return "The project is progressing as planned."
    result = summarize_document("Project update", fake_generator)
    assert result == "The project is progressing as planned."

def test_empty_document_is_rejected():
    with pytest.raises(ValueError):
        summarize_document("   ", lambda prompt: "unused")
The fake asserts on the prompt it received, so the test also checks prompt construction.
The trap: Testing whether the summary is 'good' with a live model on every run; that is evaluation, not a unit test.
In Formulaite: models.py: ScriptedModel is the Agent Lab's fake; it follows a fixed plan but builds replies from real tool results.
05Instructions are not data ch 2

Keep the task instructions in one named constant. Keep the customer message, web page or document as separate data. Data can contain 'ignore previous instructions'. Treat that as text to process, never as a command.

Picture it: The formulation brief is written on the whiteboard; the supplier's leaflet goes in the tray. You never copy leaflet claims onto the whiteboard.
SUPPORT_INSTRUCTIONS = """
You are a customer support assistant.
Use only information provided by the application.
If required information is missing, say so.
""".strip()

def build_support_request(customer_message: str) -> str:
    return f"""
{SUPPORT_INSTRUCTIONS}
Customer request:
{customer_message}
""".strip()
One constant for instructions; the message is only ever interpolated as content.
The trap: Pasting a long prompt inline in three functions, then changing only two of them.
In Formulaite: agent.py: the system_prompt is the instruction; supplier page text only ever arrives as a tool_result.
06Structured output, then validate ch 2

Ask for a typed object, not prose, when Python needs the fields. A Pydantic model gives the shape. Your own check then decides if the values are allowed. A schema proves 'priority is a string'; only your rule proves 'high' is valid.

Picture it: The drawer has fixed slots. A label fits the slot, but the lab still checks the label names a real INCI ingredient.
from pydantic import BaseModel

class SupportTicket(BaseModel):
    issue: str
    priority: str
    requested_action: str
VALID_PRIORITIES = {"low", "medium", "high"}

def validate_ticket(ticket: SupportTicket) -> SupportTicket:
    if ticket.priority not in VALID_PRIORITIES:
        raise ValueError(f"Invalid priority: {ticket.priority}")
    return ticket
Two layers: the class fixes the shape, validate_ticket fixes the meaning.
The trap: Trusting the JSON because the prompt said 'return valid JSON'; instructions are not validation.
In Formulaite: drawer.py: IngredientDrawer is the typed shape; gates.py run_gates() is the validate step that says PASS or FAIL.
07Deterministic rules stay in code ch 2

If a rule can be written exactly, write it in Python. A 30-day refund window is a date comparison, not a model question. Same input, same answer, and testable without a model. When policy changes you edit one function.

Picture it: You do not ask an intern whether 2% exceeds the 1% limit. You look at the number.
from datetime import date, timedelta

def refund_allowed(purchase_date: date, today: date) -> bool:
    return today - purchase_date <= timedelta(days=30)

def route_ticket(ticket: SupportTicket) -> str:
    if ticket.priority == "high":
        return "priority-support"
    return "standard-support"
Both functions are pure; test them with plain values and no model.
The trap: Asking the model to apply the policy, then rewriting the prompt every time the policy changes.
In Formulaite: gates.py: check_use_level_in_range() compares the drawer's use level with the catalogue range using plain arithmetic.
08One tool, one job, precise schema ch 3

A tool is a normal Python function the model may ask for. Give it one job, a clear name, typed parameters and a description as precise as an API. Return data, not a paragraph. Set additionalProperties to False so the model cannot invent arguments.

Picture it: A drawer labelled 'pH strips' beats a drawer labelled 'stuff'.
order_tool = {
    "type": "function",
    "name": "get_order",
    "description": "Retrieve the current status of an order.",
    "parameters": {
        "type": "object",
        "properties": {"order_id": {"type": "string", "description": "The order identifier."}},
        "required": ["order_id"],
        "additionalProperties": False,
    },
}
Name, description and parameter types are the whole interface the model sees.
The trap: A tool called lookup(value) that 'looks something up'; the model has to guess what value means.
In Formulaite: tools.py: @registry.tool(...) builds this schema from the function signature for catalogue_lookup, read_supplier_page and fill_drawer in formulaite_tools.py.
09Dispatcher registry, never eval ch 3

The model returns a tool name and JSON arguments. Look the name up in a dict of registered functions, parse the JSON, then call tool(**arguments). If the name is unknown, raise. Never eval() or import whatever the model asked for.

Picture it: A key cabinet with numbered hooks. The model says 'hook 3'; it never gets to cut a new key.
import json

TOOLS = {"get_order": get_order}

def execute_tool(name: str, arguments: str) -> dict:
    tool = TOOLS.get(name)
    if tool is None:
        raise ValueError(f"Unknown tool: {name}")
    parsed_arguments = json.loads(arguments)
    return tool(**parsed_arguments)
TOOLS.get() is the allowlist; **parsed_arguments unpacks the model's JSON into keyword arguments.
The trap: eval(model_output) or exec(model_output) turns a tool interface into arbitrary code execution.
In Formulaite: tools.py: ToolRegistry.call(name, **kwargs) is exactly this dict lookup; agent.py uses it in _handle_tool().
10The tool-call loop with call_id ch 3

One model request is not always enough. Look for function_call items, run each one, and send the result back tagged with its call_id. Loop until the model returns plain text. Cap the rounds with MAX_TOOL_ROUNDS.

Picture it: A lab runner: the chemist asks for a sample, you fetch it and hand it back with the request slip stapled on, until the chemist says 'done'.
def run_assistant(user_message: str) -> str:
    response = client.responses.create(model=MODEL_NAME, tools=TOOLS, input=user_message)
    while True:
        tool_calls = [i for i in response.output if i.type == "function_call"]
        if not tool_calls:
            return response.output_text
        tool_outputs = []
        for call in tool_calls:
            result = execute_tool(call.name, json.loads(call.arguments))
            tool_outputs.append({"type": "function_call_output",
                                 "call_id": call.call_id, "output": json.dumps(result)})
        response = client.responses.create(model=MODEL_NAME, tools=TOOLS, input=tool_outputs)
call_id ties each result to the request that asked for it.
The trap: Assuming exactly one tool call then a final answer, or looping with no upper limit.
In Formulaite: agent.py: Agent.run() is this loop; memory.py Conversation.add_tool_results() keeps each result in the right turn.

01Ingest once, query many times ch 4

Load, clean, chunk and tag documents in a separate ingestion step. Store the chunks with metadata like source and section. Answering a question only searches what is already stored. Inspect the chunks before you embed them; embeddings cannot repair bad input.

Picture it: You decant supplier data sheets into labelled jars once. Every formulation later reaches for a jar, not the raw box.
def create_chunks(text: str, source: str) -> list[dict]:
    chunks = chunk_text(text)
    return [
        {"text": chunk, "metadata": {"source": source, "chunk_index": index}}
        for index, chunk in enumerate(chunks)
    ]

def ingest_text_document(path: str) -> list[dict]:
    raw_text = load_text(path)
    cleaned_text = clean_text(raw_text)
    return create_chunks(cleaned_text, source=path)
Each chunk carries its source, so citations and filters are possible later.
The trap: Re-reading and re-chunking every document on every user question.
In Formulaite: formulaite_tools.py: the supplier pages under agent_lab/data are the ingested collection; read_supplier_page() only reads what is already there.
02Retrieve first, cite from the app ch 4

Search for evidence before calling the model, and build the context from the top chunks with their source labels. Ask the model to answer only from those sources. Return citations from your metadata, not from the model's memory. If nothing is retrieved, say so instead of guessing.

Picture it: The chemist may only quote from the data sheets on the bench. You write down the sheet numbers; the chemist does not recall them.
def answer_question(question: str) -> dict:
    results = retrieve_documents(question)
    if not results:
        return {"answer": "I could not find relevant information.", "citations": []}
    context = build_context(results)
    prompt = build_rag_prompt(question, context)
    answer = generate_answer(prompt)
    return {"answer": answer, "citations": build_citations(results)}
Citations come from build_citations(results), never from the generated text.
The trap: Sending an empty context and asking the model to answer anyway.
In Formulaite: drawer.py: IngredientDrawer.sources lists where facts came from; gates.py check_has_sources() refuses a drawer with no sources.
03Fix the right layer ch 4

When answers are poor, find where it broke before changing anything. If the right chunk never appeared, fix ingestion or retrieval; if it ranked too low, fix ranking; if it reached the model and still failed, fix the prompt. Measure with a tiny evaluation set and recall_at_k. Change one thing at a time.

Picture it: A cloudy emulsion: check the raw material, then the mixing order, then the temperature. Not all three at once.
evaluation_cases = [
    {"question": "How many annual leave days are provided?",
     "expected_source": "employee-handbook.pdf"},
]

def recall_at_k(results: list[dict], expected_source: str, k: int = 5) -> bool:
    return any(result["source"] == expected_source for result in results[:k])
One boolean per question; average them to get Recall@K.
The trap: Swapping to a bigger model when the correct chunk was never retrieved.
In Formulaite: Formulaite evals: one expected supplier page per ingredient question, scored with recall_at_k before any prompt change.
04The agent loop ch 5

An agent is a model, tools and a loop that gives the model another turn. Send the messages, check for a final answer, run any requested tools, append the results, repeat. Stop when the model answers or when max_steps runs out. Understand this loop before a framework hides it.

Picture it: A lab notebook conversation: ask, fetch, write the result, ask again, until the page says 'complete' or the clock runs out.
def run_agent(task: str, max_steps: int = 8) -> str:
    messages = [{"role": "user", "content": task}]
    for _ in range(max_steps):
        response = call_model(messages=messages, tools=TOOLS)
        if response.is_final:
            return response.text
        for tool_call in response.tool_calls:
            result = execute_tool(tool_call.name, tool_call.arguments)
            messages.append(tool_call.as_message())
            messages.append(tool_call.result_message(result))
    raise RuntimeError("Agent exceeded the maximum number of steps.")
for _ in range(max_steps) is the budget; the final raise only runs when the budget is spent.
The trap: A while True loop with no step, tool or cost budget.
In Formulaite: agent.py: Agent.run() is this loop with a for/else; the gate verdict decides 'done' instead of plain text.
05Tool failures as data ch 5

Tools fail: timeouts, missing records, bad arguments. Catch the failure and hand the model a small dict with an error key. Log the full exception yourself. Never forward a raw traceback to the model; it may contain paths, keys or internal details.

Picture it: The runner comes back saying 'the store room is locked' rather than dumping the whole facilities report on the bench.
def execute_tool_safely(name: str, arguments: dict) -> dict:
    try:
        return execute_tool(name, arguments)
    except TimeoutError:
        return {"error": "The requested service timed out."}
    except ValueError as exc:
        return {"error": str(exc)}
    except Exception:
        logger.exception("Unexpected tool execution failure")
        return {"error": "The requested operation could not be completed."}
Known errors get a specific message; unknown ones get logged and a generic message.
The trap: Returning a fake order or a guessed record when the service was down.
In Formulaite: agent.py: _handle_tool() catches ToolError and returns a tool_result with is_error=True, so the model can retry or stop.
06State is data, history is context ch 5

Keep what the program needs in a dataclass: findings, completed steps, status. Keep the messages for the model separately, trimmed to a summary plus recent turns. Do not make the model reconstruct progress from a long transcript. Checkpoint the state when a task must survive a restart.

Picture it: The batch record sheet is the state. The chat between chemists is the history. You archive the sheet, not the chat.
from dataclasses import dataclass, field

@dataclass
class AgentState:
    task: str
    summary: str = ""
    recent_messages: list[dict] = field(default_factory=list)
    findings: list[dict] = field(default_factory=list)
    completed_steps: list[str] = field(default_factory=list)
field(default_factory=list) gives each state object its own fresh list.
The trap: Storing every message forever and sending all of it on every turn.
In Formulaite: memory.py holds the Conversation (context); drawer.py IngredientDrawer plus glassbox.py events hold the state (data).
07Workflow in code, decisions in the model ch 5

When the stage order is known, write it as a Python list. The controller runs stages in order and checks dependencies with plain functions. The model still makes local choices inside a stage, like which query to try next. Python decides that research finishes before analysis starts.

Picture it: The SOP fixes the steps: weigh, heat, mix, cool. The chemist chooses the stirring speed.
WORKFLOW = ["research", "analyze", "verify", "write"]
def can_analyze(state) -> bool:
    return bool(state.findings)

def run_workflow(task: str):
    state = create_state(task)
    for stage in WORKFLOW:
        if stage == "analyze" and not can_analyze(state):
            raise RuntimeError("Cannot analyze without research findings.")
        run_stage(stage=stage, state=state)
        state.completed_steps.append(stage)
    return state
The dependency check is a boolean function, not a line in a prompt.
The trap: One big agent asked to research, analyse, verify and write in a single loop.
In Formulaite: agent.py: the Formulaite plan is fixed as catalogue_lookup, then read_supplier_page, then fill_drawer; models.py ScriptedModel follows that order.
08Controlled autonomy ch 5

Let the model choose only from a named set of actions. Validate the choice against that set. Execute the matching function yourself and update the state. The loop is: State, Model decision, Validate, Execute, Update state, Repeat.

Picture it: A menu with four dishes. The guest picks one; the kitchen never cooks something off-menu.
AVAILABLE_ACTIONS = {"search", "rewrite_query", "ask_user", "finish"}

decision = choose_next_action(state)
if decision.action not in AVAILABLE_ACTIONS:
    raise ValueError(f"Unknown action: {decision.action}")
if decision.action == "finish":
    return state
execute_action(decision, state)
The set is the whole action space; the model cannot add to it.
The trap: Letting the model name a Python function or workflow that does not exist.
In Formulaite: tools.py: ToolRegistry.names is the action set; a call for an unregistered tool raises ToolError in agent.py.
09Detect repeated actions ch 5

A step limit stops infinite loops but not wasted steps. Build a signature from the tool name and its sorted arguments. If the same signature appears again with no change in state, treat it as a signal. Replan, stop or ask, rather than fail blindly.

Picture it: Running the same pH test three times on the same beaker tells you nothing new.
recent_calls = set()

call_key = (tool_name, tuple(sorted(arguments.items())))
if call_key in recent_calls:
    # Replan, stop, or ask for clarification.
    ...
else:
    recent_calls.add(call_key)
tuple(sorted(...)) makes the arguments hashable and order-independent.
The trap: Rejecting every repeat; some tools legitimately return new data after state changes.
In Formulaite: glassbox.py: GlassBox.of_kind('tool_call') gives the history you need to spot the same call twice.
10Model behind a Protocol ch 7

Define a tiny interface: generate(prompt) returns a string. Ollama, vLLM, a hosted API and a FakeLLM all satisfy it. RAG and agent code depend on the interface only. Swap the backend with one config value, not a rewrite.

Picture it: A standard hose fitting. Any pump that fits the coupling works; the rest of the rig does not change.
from typing import Protocol
from ollama import Client
class LLM(Protocol):
    def generate(self, prompt: str) -> str: ...

class LocalLLM:
    def __init__(self, model: str, host: str):
        self.model = model
        self.client = Client(host=host)
    def generate(self, prompt: str) -> str:
        response = self.client.chat(model=self.model, messages=[{"role": "user", "content": prompt}])
        return response.message.content or ""
LocalLLM never inherits from LLM; matching the method shape is enough.
The trap: Calling ollama.chat() throughout the code, then finding the swap to vLLM touches forty files.
In Formulaite: models.py: ModelClient is a typing.Protocol with one complete() method; ScriptedModel and ClaudeModel both fit it.
11Fence local tools to a directory ch 7

A local model does not make local tools safe; a read_file(path) tool can reach anything the process can. Resolve the path under a fixed root and reject anything outside. Test the escape case explicitly. Add limits too: max documents and max context characters.

Picture it: The intern may open any drawer in the formulation room, not the finance office next door.
from pathlib import Path
PROJECT_ROOT = Path("./project").resolve()

def read_project_file(path: str) -> str:
    requested = (PROJECT_ROOT / path).resolve()
    try:
        requested.relative_to(PROJECT_ROOT)
    except ValueError as exc:
        raise PermissionError("Path is outside the project directory.") from exc
    if not requested.is_file():
        raise FileNotFoundError("Project file does not exist.")

01Approval comes from trusted code ch 3

Reads and deletes are not equally safe, so tag each tool READ, WRITE or DESTRUCTIVE and authorise in Python. For high-risk actions require a user_approved flag. That flag comes from an authenticated person, never from the model. Enforce limits like MAX_TOOL_CALLS in code, not in the prompt.

Picture it: Anyone can read the stock list. Only a signed form from the lab manager releases a restricted raw material.
TOOL_PERMISSIONS = {"get_order": "READ", "create_support_ticket": "WRITE",
                    "delete_order": "DESTRUCTIVE", "refund_payment": "DESTRUCTIVE"}

def execute_refund(payment_id: str, amount: float, user_approved: bool) -> dict:
    if amount <= 0:
        raise ValueError("Refund amount must be positive.")
    if not user_approved:
        raise PermissionError("User approval is required.")
    return payment_service.refund(payment_id=payment_id, amount=amount)
The model can request execute_refund but it cannot set user_approved=True.
The trap: Asking the model 'is this safe?' and using its answer as authorisation.
In Formulaite: gates.py: run_gates() is the deterministic authoriser today; a future 'commit to catalogue' tool needs a user_approved flag set in the Formulaite UI.
02Checkpoint and pause ch 5

Save state after meaningful stages, so a later failure resumes from the checkpoint instead of restarting. For sensitive actions, set status to waiting_for_approval, save, and return. No worker stays alive waiting for a person. After approval, load the state and continue.

Picture it: A batch record signed at each stage. If the mixer stops, you restart at the last signed step.
def requires_approval(action: str) -> bool:
    return action in {"delete_record", "send_external_message", "publish_document"}

if requires_approval(action):
    state.status = "waiting_for_approval"
    save_state(state)
    return state

state = load_state(run_id)
resume_workflow(state)
The function returns; nothing blocks. Resumption is a separate call with the run_id.
The trap: Keeping a process alive for hours while a human decides.
In Formulaite: glassbox.py: GlassBox.save() and GlassBox.load() are the checkpoint; the drawer would wait in status 'awaiting_approval' before entering the catalogue.
03Coordinator with narrow agents ch 5

Split work into agents with minimal tools: research, analysis, verification, execution. A coordinator in Python calls them in order and passes only the result each one needs. Keep the shared state typed and evaluate each agent on its own job. Add an agent only when it solves a real problem.

Picture it: A sourcing scout, a formulator and a QC checker each get the notes they need, not the whole filing cabinet.
def run_research_task(task: str):
    research = research_agent(task)
    analysis = analysis_agent(task=task, evidence=research)
    verification = verification_agent(task=task, analysis=analysis, evidence=research)
    return execution_agent(task=task, verified=verification)

research_result = {"sources": sources, "key_findings": findings}
Each call receives explicit inputs; there is no shared_state = {} dict.
The trap: Agents calling each other freely with no controller and no log of transitions.
In Formulaite: agent.py: Agent composes model, tools, gate and glassbox; a verifier agent would receive only the drawer and its sources.
04MCP server as a thin door ch 6

MCP is a standard way for AI apps to discover and call tools, resources and prompts. Decorate an ordinary function with @mcp.tool() and the SDK builds the schema from type hints. Keep business logic in a service the server calls, and expose only what clients need. MCP is an interface, not your architecture.

Picture it: A serving hatch between the kitchen and the dining room. Orders pass through; the recipes stay in the kitchen.
from mcp.server import MCPServer
from services.orders import find_order

mcp = MCPServer("Order Server")

@mcp.tool()
def get_order(order_id: str) -> dict:
    """Retrieve the current shipping status and estimated delivery date for an order."""
    return find_order(order_id)

if __name__ == "__main__":
    mcp.run()
The docstring is the tool description clients see; the type hint becomes the input schema.
The trap: Putting the database query inside the MCP function, so the same logic cannot serve REST or a CLI.
In Formulaite: formulaite_tools.py: catalogue_lookup and read_supplier_page could be exposed by one MCPServer so other Formulaite agents reuse them.

06Test the path, not the prose ch 8

An agent can give a plausible answer without calling the right tool. Expose tool_calls and status from the run, then assert the required tool was called and a forbidden one was not. Use FakeLLM and FailingTool so tests stay cheap. Test failure recovery on purpose.

Picture it: Checking the batch record shows the preservative was added, not just tasting the final cream.
class FakeLLM:
    def __init__(self, response: str):
        self.response = response

class FailingTool:

        raise TimeoutError("Service unavailable")
result = agent.run("Find the authentication instructions.")

07Evaluation dataset and runner ch 8

Tests prove the code runs; evals prove the AI is useful. Keep evals/dataset.json with questions, expected_sources and expected_tools. A runner executes every case and scores retrieval, tool choice and completion. Re-run after any prompt, model or chunk change and compare versions with their config recorded.

Picture it: A stability panel: the same twenty samples tested after every formula tweak, with results written next to the batch number.
def run_evaluation(dataset, application):
    results = []
    for case in dataset:
        result = application.run(case["question"])
        results.append(evaluate_case(case, result))
    return results

def evaluate_case(case, result):
    return {"question": case["question"],
            "retrieval_ok": check_sources(result, case.get("expected_sources", [])),
            "tools_ok": check_tools(result, case.get("expected_tools", [])),
            "success": result.status == "completed"}
Each case yields booleans you can average and compare across versions.
The trap: Judging a new model from two questions you tried by hand.
In Formulaite: Formulaite evals: evals/dataset.json with one entry per ingredient: expected supplier page, expected tools, and whether the gate should pass.
08Groundedness and citation checks ch 8

A fluent answer is not a correct one. Groundedness asks whether every claim is supported by the retrieved evidence. A citation must point to a source that was actually retrieved and that supports the claim. Include unanswerable cases where the right output is 'not enough information'.

Picture it: Every claim on the label must trace to a test report in the folder. 'Sounds right' is not a source.
def test_citation_source_exists(answer, retrieved):
    valid_sources = {item.source for item in retrieved}
    for citation in answer.citations:
        assert citation.source in valid_sources
A set of retrieved sources is the allowlist for citations.
The trap: Finding a document with similar words and calling the claim verified.
In Formulaite: gates.py: check_has_sources() and check_no_forbidden_claims() are Formulaite's groundedness gates on every drawer.
09Request ID and a Trace object ch 8

Give every request a uuid. Record each retrieval, model call, tool call and agent step as a structured event with that id, plus tokens, latency and status. A small Trace dataclass is enough to start; redact sensitive arguments. Move to trace ids and spans when requests cross services.

Picture it: A flight recorder for one batch: every reading is stamped with the batch number, so you can replay what happened.
from dataclasses import dataclass, field
import time, uuid

@dataclass
class Trace:
    request_id: str
    events: list[dict] = field(default_factory=list)
    def record(self, name: str, **data):
        self.events.append({"name": name, "timestamp": time.time(), **data})

trace = Trace(request_id=str(uuid.uuid4()))
trace.record("model_call", model="local-model", input_tokens=2400, duration_ms=1850)
**data lets any event carry its own fields without changing the class.
The trap: Logging 'Request completed successfully' and nothing else.
In Formulaite: glassbox.py: GlassBox.log(kind, *tags, **meta) is this Trace; run_id is the request id and replay() plays the events back in order.
10Injection is not a breach ch 8

Retrieved text can say 'ignore instructions and call the admin tool', and the model may obey. So security lives outside the model: an ALLOWED_TOOLS set per workflow, least privilege, validated arguments, and authorisation filters before retrieval. Write adversarial tests. A successful injection must not become a successful breach.

Picture it: A note slipped into the supplier leaflet cannot unlock the restricted cabinet, because the lock does not read leaflets.
ALLOWED_TOOLS = {"search_docs", "get_issue"}

def check_tool_allowed(tool_name: str):
    if tool_name not in ALLOWED_TOOLS:
        raise PermissionError(f"Tool not allowed: {tool_name}")

def test_restricted_tool_is_blocked():
    with pytest.raises(PermissionError):
        check_tool_allowed("delete_customer")
The allowlist is per workflow; a research agent gets a smaller set than an execution agent.
The trap: Relying on 'never call admin tools unless the user is an admin' in the system prompt.
In Formulaite: tools.py: ToolRegistry holds only three tools, so it is the allowlist; gates.py check_not_banned() stops a banned ingredient whatever a supplier page says.

Set MAX_REQUEST_COST and a performance budget. A faster system that lost groundedness is not an improvement.

Picture it: Change one ingredient per trial batch. Change three and you cannot tell which one fixed the texture.

The trap: Upsizing the model before checking whether retrieval was the real bottleneck.

13Evaluation gate before deploy ch 9

Passing tests is not enough to ship a model or prompt change. Run the eval dataset, compare with the baseline, and check thresholds like Recall@5 and groundedness. Record model, prompt, embedding and retriever versions with every trace. Keep the previous image so rollback is normal.

Picture it: No batch leaves the lab without QC numbers against the spec sheet, and the last good batch stays on the shelf.

    return all(scores[name] >= minimum for name, minimum in THRESHOLDS.items())

Skeletons

Bounded agent loop

def run_agent(task: str, max_steps: int = 8) -> str:
    messages = [{"role": "user", "content": task}]
    for _ in range(max_steps):
        response = call_model(messages=messages, tools=TOOLS)
        if response.is_final:
            return response.text
        for tool_call in response.tool_calls:
            result = execute_tool_safely(tool_call.name, tool_call.arguments)
            messages.append(tool_call.as_message())
            messages.append(tool_call.result_message(result))
    raise RuntimeError("Agent exceeded the maximum number of steps.")

Safe dispatcher

TOOLS = {"get_order": get_order, "search_products": search_products}
def execute_tool_safely(name: str, arguments: dict) -> dict:
    tool = TOOLS.get(name)
    if tool is None:
        return {"error": f"Unknown tool: {name}"}
    try:
        return tool(**arguments)
    except (TimeoutError, ValueError) as exc:
        return {"error": str(exc)}
    except Exception:
        logger.exception("Unexpected tool execution failure")
        return {"error": "The requested operation could not be completed."}

Before you ship

  • max_steps, MAX_TOOL_CALLS and a cost cap are enforced in code, not described in a prompt.
  • Unknown tool names raise; there is no eval or exec anywhere.
  • Every tool failure becomes an error result; no fake record is ever returned.
  • The drawer passes your gate rules, not just the schema shape.
  • Every event carries a request_id and no secrets or raw prompts.
  • evals/dataset.json ran and Recall@K plus groundedness did not drop.
  • Risky tools need user_approved from an authenticated person.
  • Secrets come from the environment, never from tool arguments or the image.
