01 · Where this is going

The whole agent is one loop with four parts

By the end of this track you have an agent that fills the Ingredient Drawer for any INCI name, refuses banned ones, admits unknown ones, and leaves a replayable record of every decision. Nothing later replaces this loop. Later modules only add things either side of it: a router in front, a persistent memory beside it, the real supplier-page reader behind the tools.

Request→ Loop: model ↔ tools ↔ gate→ Drawer+ Glass Box trace→ Router (next)→ Real page reader (next)

The rule every book agrees on: the model proposes, plain code decides. The model can only ask for tools from a menu; a gate written in ordinary Python has the last word.

05 · So what did you just see?

Four things the runs prove

The gate, not the model, decided

In the repair run the model submitted a drawer at step 7 and the gate refused it: “use_level_pct 50.0% is outside catalogue range 1.0-10.0%”. The reasons went back as a tool_result, the model resubmitted, and the gate passed at step 9. Plain code had the last word.

Retries are cheap when they are specific

The repair cost exactly one extra model call: 4 calls and 10 events instead of 8 events on the happy path. That is Anthropic's evaluator-optimizer pattern in miniature.

Saying “no” is a first-class outcome

The banned run stopped after 6 events and the unknown-ingredient run after 6. Neither crashed, neither invented a drawer. The books call this making refusal a legal path.

Every step is on the record

All 9 drawer sections, every tool input and output, every verdict — one log(kind, *tags, **meta) call each. That single flexible signature is why *args/**kwargs exist.

Sources and what was left out

Code: Formulaite-Agent-Lab/agent_lab/ — the file tiles in section 02 name them in reading order. Traces: traces/*.json, produced by python3 -m agent_lab … --save.

Books (converted to Markdown in books-md/, per-book notes in docs/book-notes/, synthesis in docs/agent-infrastructure-notes.md): AI Agents with Python ch. 1.2 “Understanding the Agent Loop”, ch. 4 “Function Calling and Tool Integration”; Python AI Programming 2e — the fifteen-line loop with max_steps; AI Programming with Python for Developers — “the model decides what it wants, Python decides what is allowed”; Modern Loop Engineering — observation, reasoning, action, evaluation cycles; The 7 GenAI Architectures — the Termination Test and the explicit give-up field; Production AI Engineering — “the model proposes, the policy layer decides, the executor acts”; Building Autonomous AI Agents with Claude ch. 2 — logging reasoning / action / observation per iteration; Learn AI Agents by Building ch. 9 — refusal as a first-class route; AI Agents Playbook — cost as an architecture property.

Anthropic docs: Tool use overview (tools → tool_use → tool_result with tool_use_id), Tool Runner (client.beta.messages.tool_runner, @beta_tool), Structured outputs, and the “Building effective agents” essay (workflows vs agents; the five patterns).

Deliberately left out: streaming, prompt caching, the real HTTP page reader, persistent memory, cost budgets beyond max_steps, and multi-agent orchestration. The notes file says which book chapter covers each.

How you'd have built this yourself

Prove the single move first: a ten-line script that sends one catalogue_lookup tool to a model and prints the tool_use block back. Only when that works, wrap it in a loop with a step budget. Then add the Glass Box (a list plus a log method), because the moment you have a loop you need to see it. Then the gate, because the moment the model produces a drawer you need to check it. Then swap in the scripted model, because you want to run the whole thing a hundred times without paying. Every file in the lab is one of those steps, in that order.

The bug you would probably have hit: an empty Glass Box is “falsy” because it defines __len__, so glassbox or GlassBox() silently throws away the box you passed in. The fix is if glassbox is not None. It is kept in agent.py with a comment.

Catalogue percentages and supplier pages are teaching fixtures, not regulatory advice.
